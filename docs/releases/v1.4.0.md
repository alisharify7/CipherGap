# CipherGap 1.4.0

CipherGap now supports **Eitaa Web** and **Telegram Web A** alongside Bale Web.
Update the extension and refresh each messenger tab. Chrome needs site access to
`web.eitaa.com` and `web.telegram.org/a/`; Firefox uses the same source with its
generated event-page manifest. Telegram Web K and username-only hashes are outside
this release’s supported DOM/URL contract.

All three platforms share AES-GCM, P-256 exchange, six-digit verification,
15-minute deadlines, inline accept/decline, chat keys, language/theme/pause state,
file encryption and the local media viewer. The platform files contain only native
DOM and send/download hooks. No generated messenger classes are selected.

Use **Encrypt** in CipherGap’s chat toolbar on Eitaa or Telegram. **Encrypted file**
opens a separate picker; only encrypted `.cgpe` files reach the messenger’s normal
file preview. Confirm that preview to send. Ordinary messenger controls remain
ordinary. Click **Decrypt & view** to preview images or play audio/video; **Download**
saves the authenticated original. The downloaded-file fallback remains available.

Eitaa reads only the requested ciphertext document from its cache or native
Service Worker transfer. Telegram captures its native Blob download. Localized Persian/Arabic digits are restored only for wire parsing; original
plaintext is preserved. Native
message timestamps and counters remain outside protocol parsing. On Telegram,
installation-link previews disappear with the footer while CipherGap is enabled.

Automatic file receipt is opt-in. Telegram has no native machine-readable message
sending time: its initial one-second settling period and observed message-ID
baseline prevent history downloads. Files that arrive during initial settling,
legacy undated exchange messages, app-passcode-encrypted caches and unsupported
attachment layouts can require the explicit fallback/new-request path. Playback
starts only after whole-file authentication; the 100 MB limit still applies.

See [browser validation](../browser-validation.md) for the distinction between
live account checks and isolated two-party fixtures. Android, Telegram Web K,
slow near-limit transfers and other host UI languages were not validated.

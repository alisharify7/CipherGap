# CipherGap 1.6.0

Rubika Web and Soroush Plus Web now use the same encrypted messaging and file
flows as Bale, Eitaa and Telegram Web A. Floating controls follow the width and
position of the native message surface, including when the window resizes.

## Install or update

Chrome: reload the unpacked extension, then refresh each messenger tab.
Firefox: load the updated Firefox package temporarily through `about:debugging`;
standard permanent installs still require Mozilla signing.

For the new messengers, both participants need 1.6.0. Open your conversation,
choose **Set up secure chat**, accept the inline request, then compare the
six-digit code through a trusted channel and verify it on both devices within
15 minutes. Ordinary messenger send/attachment controls remain ordinary.

**Encrypted file** hands a `.cgpe` file to the native preview. Confirm its send;
the recipient can decrypt, preview supported media and download the original.
Existing keys, text packets, file containers and sticker formats are unchanged.

## Validation

- Chromium and Firefox: two independent peer contexts, ECDH/SAS, inline consent,
  expired requests, encrypted Unicode/image-backed emoji, native file handoff,
  static/animated stickers, preview/playback, exact downloads and pause.
- Live account sessions from Your Chrome at the supplied Rubika/Soroush links:
  encrypted text and emoji, native file previews, file delivery, decryption and
  exact original downloads. A second Soroush message after file preview succeeded.
- Two-party key exchange was tested with isolated DOM fixtures, not two live
  accounts on these new messengers. Keep this distinction when reporting coverage.

This release adds **desktop** support. The published Android 0.1.1 APK still
supports Bale, Eitaa and Telegram Web A; new mobile adapters are not claimed by
this desktop release. See [browser validation](../browser-validation.md).
